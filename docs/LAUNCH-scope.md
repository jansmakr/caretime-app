# 1차 출시 범위

**1차는 전국 하나의 지역 현장톡이다.** 2026-10-03 에 다시 좁혔다.

보호자가 야간에 묻는 것은 "마곡동인데 애가 열이 40도예요. 어디 열었나요?" 이고
여기에는 병원 목록도, 항목별 상태도, 진료시간도 필요 없다.

## 이번에 바꾼 것 (2026-10-03)

| 전 | 지금 | 왜 |
|---|---|---|
| 지역별로 방이 갈릴 수 있었다 | **전국 하나의 방** + "내 지역 보기" 필터 | 방을 나누면 다 빈 방이 된다. 하나로 합치면 글이 모여 활기가 보인다 |
| 글이 병원에 걸렸다 | **글쓴이의 구**에 걸린다 | 병원 이름은 본문에 그냥 쓴다. 이름이 갈라져도 괜찮다 |
| 병원 목록·상세를 골랐다 | 닫았다 (404) | 고르는 자리가 없으면 상세도 갈 길이 없다 |
| 글을 30일 뒤 지우고 24시간 뒤 감췄다 | **쌓는다** | "로뎀 밤 10시까지"는 몇 년 뒤에도 유효하다 |
| — | 기본 최근 1개월 · "이전 글도 보기" | 기간이 곧 검색이다. 키워드 검색은 2차 |
| 본문 300자 | **1000자** + 남은 글자 | 음성 입력(키보드 마이크)은 300자에서 잘린다 |
| 시행일을 날짜로 박았다 | **미정** | 준비된 날을 시행일로 적고 그날 연다 |

내 지역은 **이 기기에만** 남는다(localStorage). 서버에 넣으면 수집 항목이 늘고
방침에 "거주 지역"이 붙는다 — 구는 글에 이미 붙어 저장되므로 따로 들고 있을
이유가 없다. 서버가 못 읽으므로 첫 화면은 전국이고, 마운트 뒤 내 지역으로 바뀐다.

**키워드 검색을 넣지 않았다.** 글이 수십 건일 때 검색창은 빈 결과를 만드는 장치이고
(0건을 본 사람은 나간다), 화면의 결정을 하나 늘린다(원칙 1·10). 지역 + 기간 두 축으로
충분하다. 한국어는 Postgres 기본 FTS 로 안 쪼개져서 `pg_trgm` 이 필요하다 — 2차.

**전국 시군구 목록은 서울 25구만 채워져 있다.** 빠뜨린 것이 아니다 — 229개를
기억으로 적으면 틀린 이름이 섞이고, 틀리면 그 구를 고른 사람의 글이 엉뚱한 지역에
붙는다. 나머지 시도는 시/도만 고른다. 채우는 방법은
`src/features/regions/sigungu.ts` 주석에(행정표준코드 목록을 그 파일에 옮긴다).

## 내린 것 (코드는 지우지 않았다)

되살리는 방법이 전부 한 파일에 있다: `src/lib/demoContent.ts`.

| 무엇 | 어떻게 내렸나 | 왜 | 되살리는 조건 |
|---|---|---|---|
| 항목별 상태 표시 | `showServiceBreakdown = false` | 3분할(봉합·화상·기타)은 "야간 소아 외상" 설계다. 1차 지역의 달빛어린이병원이 보는 것은 발열·감기·구토·설사·중이염 — 항목과 병원이 어긋나 있다 | 항목 체계를 실제 진료과목에 맞춰 다시 세운 뒤 |
| 진료시간 · 내원 마감 | `showAdmissionHours = false` | 확인된 진료시간이 한 곳도 없다. 모든 카드가 같은 "정보 없음"을 그린다 | 수동 입력 2곳의 진료시간을 확인해 넣은 뒤 |
| 좌표 · 거리 · 이동시간 | `showDemoDistance` · `showTravelEstimate = false` (이미) | 고정 데모 출발점 기준이라 '내 주변'이 아니다 | 지도 어댑터를 붙일 때 |
| 병원 로그인 · 입력 화면 | `showPartnerEntry = false` → `/partner*` not found | 참여 병원 0곳. 아무도 들어갈 수 없는 문을 보호자 화면 헤더에 붙여 두지 않는다 | 첫 참여 병원이 생길 때 |
| **의료기관 목록 · 상세** | `showHospitalDirectory = false` → `/search`·`/hospital/[id]` not found | 글을 병원이 아니라 구에 걸기로 했다. 고르는 자리가 없으면 상세도 갈 길이 없다 | 2차에 병원을 다시 붙일 때 |
| 공공데이터 연동 | **멈춘다.** 코드 없음 — `docs/DATA-INVENTORY.md` 의 스키마 초안과 migration 초안은 적용하지 않은 채 둔다 | 1차에 필요 없다. 지역 현장톡은 병원 목록 없이 돈다 | 2차 |
| 동시수정 409 | 코드는 그대로. 쓰는 화면이 닫혀 있어 **경로가 없다** | 병원 입력 화면이 1차에 없으므로 동시에 고칠 사람이 없다 | 병원 화면을 열 때 함께 |

판정 규칙은 아무것도 바꾸지 않았다. 접기 규칙(`mergeConservative`),
항목 판정(`deriveServiceBreakdown`), 마감 판정(`lib/hours`)은 그대로 돌고
**표시만** 닫혔다. 카드의 "전화를 앞으로 끌어올리는" 판정은 여전히 마감 상태를
읽는다 — 보여 주지 않는 것과 판정에서 빼는 것은 다른 일이다.

## 진료과목·연령을 열었다 (2026-10-06)

소아 열상·화상이 우선 관심사지만 **서비스는 전 과목·전 연령으로 연다.**

- 작성창의 주제 칩(찢어진 상처·화상·그 밖)을 **없앴다.** 칩이 그 둘을 먼저 보여주면
  열·감기로 온 사람이 "내 건 해당 안 되나" 하고 멈춘다. 글은 지역 하나로 흐르고
  찾는 축은 지역·기간이라 분류할 이유도 없다.
- `field_reports.category` 컬럼은 남겼다. 모든 글이 같은 값으로 들어가고, 2차에
  분류가 필요해지면 그 컬럼을 쓴다. 목록의 분류 칩도 뗐다 — 모든 글이 같은 값이면
  그 줄은 아무것도 말하지 않는다(원칙 4).
- 공유 문구에서 "열상·화상"을 뺐다. 공유받은 사람에게 대상을 좁혀 보이면 안 된다.
- **진단·치료 조언 금지는 그대로다.** 그건 대상을 좁히는 말이 아니라 하지 말아야
  하는 일이다 — 작성창 문구와 약관 3항에 남아 있다.

남아 있는 좁히는 표현은 닫힌 화면(`/search` 의 소아 진료 조건, 병원 입점 폼)과
운영에 나가지 않는 데모 시드뿐이다. 그 화면을 다시 켤 때 함께 본다.

## 의료기관 추가 요청 — 화면이 없다

`hospital_requests` 표·서버 라우트·테스트는 있는데 **어느 화면에도 연결된 적이
없다**(만든 커밋부터 그랬다). 1차에는 병원 목록이 없어서 "목록에 없는 병원"이라는
개념 자체가 없고, 병원 이름은 본문에 그냥 쓴다. 2차에 목록과 함께 붙인다.

## 2차에 병원을 다시 붙일 때 — 미리 적어 두는 한 줄

이미 만들어 둔 것을 켠다: 로그인·입점 신청·병원 입력 화면·공개 뷰·`hospital_id` 컬럼.
"이 의료기관 글만 보기"는 **화면을 새로 만드는 것이 아니라 그 방의 필터 하나**다.

⚠️ 병원이 쓴 글에 배지를 붙일 때: **출처 표시이고 추천이 아니다.** 의료법 27조
(환자 유인·알선) 때문에 **정렬·노출 가중치에 쓰지 않는다.** 배지가 순서를 바꾸는
순간 그것은 광고가 된다. 같은 이유로 `hospitals` 에 결제·제휴 필드를 두지 않고,
검색 정렬이 그 값에 접근할 경로 자체를 만들지 않는다
(`features/hospitals/types` 설계 규칙 ②).

## 2차 자리 — 빈 방이 말을 거는 장치 (챗봇, **1차에 넣지 않는다**)

아이디어: 글이 0건일 때 챗봇이 먼저 말을 걸어 첫 글을 유도한다.

1차에 넣지 않는 이유 셋. 전부 되돌리기 어려운 쪽이다.

1. **PRD 절대 원칙과 부딪힌다** — AI 가 의료 판단을 하지 않는다. 밤중에 "열나요"
   라고 쓴 사람에게 챗봇이 한 줄만 답해도 그게 판단이 된다. 그 선을 지키는 문구를
   미리 다 쓸 수 없다.
2. **챗봇 글은 "가상 데이터"와 같은 종류다** — 사람이 쓴 것이 아닌 글이 목록에
   섞인다. 그 문제로 배너를 두 번 고쳤다.
3. **1인 운영에서 통제할 수 없다** — 새벽 3시에 무엇을 말하는지 보고 있을 사람이
   없다. 고장이 조용히 지나간다.

대신 **빈 방 화면이 말을 건다.** `components/chat/EmptyRoomLead` 의 예문 두 줄이
그 자리다 — 사람이 쓴 문장이고, 지금 하나 · 평소 하나로 두 종류를 보여 준다.
챗봇을 다시 검토한다면 먼저 답해야 하는 것은 "무엇을 **말하지 않는지**"다.

## 2차 자리 — 소식 듣기 (내 글에 답이 달리면 알림)

**1차에는 알림이 없다. 알고 간다.**

앞서 "답이 달린 걸 어떻게 아는가"의 답이 이것이다 — 1차에는 **다시 들어와서 보는
것**이 유일한 길이다. 그래서 홈 화면 바로가기를 만든다(아이콘 하나로 다시 열린다).

2차에 로그인과 함께 연다. 로그인이 먼저인 이유:

- 알림을 보내려면 **어디로 보낼지**를 저장해야 한다(푸시 구독 토큰 또는 이메일).
  그건 수집 항목이 느는 일이고 방침을 고쳐야 한다 — 되돌리기 어려운 쪽이다.
- 지금 "내 글"은 게스트 세션(쿠키)에 묶여 있다. 쿠키를 지우면 끊긴다. 그 위에
  알림을 얹으면 **받다가 조용히 안 받게 되고**, 받는 사람은 이유를 모른다.
- 1인 운영에서 발송 실패를 보고 있을 사람이 없다. 로그인이 있으면 적어도 화면
  안에서 "답 1건"을 보여 주는 길이 먼저 생긴다 — 발송 없이도 절반은 해결된다.

순서: 로그인 → 화면 안 알림(읽지 않은 답) → 그다음에야 푸시·메일.

## 샘플 글 — 운영에 넣지 않는다

빈 방으로 시작한다. 이유는 둘 중 어느 쪽으로도 빠져나갈 수 없기 때문이다.

- 실제 병원 이름이 든 지어낸 글 = **그 병원에 대한 허위 정보**다
- 가상 병원 이름을 쓰면 "모두 가상 데이터" 배너를 되살린다

들어갈 경로가 없는지 확인했다(2026-10-06):

| 경로 | 상태 |
|---|---|
| `supabase/seed.sql` | **글 insert 가 한 줄도 없다.** 병원·capabilities·상태만 있다 |
| `seed.sql` 이 운영에 실행되는가 | 아니다. `db.seed.sql_paths` 는 `db reset`(로컬) 때만 읽힌다. `db push` 는 migration 만 올린다 |
| migration 안의 글 insert | 없다 |
| 화면의 가상 글(`features/chat/seed.ts`) | `showDemoReports` 로만 나온다. 그 플래그를 **운영 빌드에서 환경변수로 열 수 없게** 막았다(`lib/demoContent`) — `NEXT_PUBLIC_DEMO_CONTENT` 를 켜도 `NODE_ENV=production` 이면 나오지 않는다 |

## 남은 것

1. 보관 기간과 삭제 로직 — **완료** (`20261004_retention_purge`, 실 DB 테스트 11개)
2. `/terms` · `/privacy` 라우트 자리 — 본문은 사용자가 준다
3. 지역 현장톡이 첫 화면에서 잘 보이는가
4. 전체 점검 + 띄워서 화면 확인

## 1차에 실제로 돌아야 하는 것

- 홈에서 현장톡으로 들어간다
- 지역을 고르지 않고도 첫 글을 쓸 수 있다
- 글이 서버에 남고 **계속** 공개된다 (24시간 공개 창을 껐다, migration 20261007)
- 다른 사람에게 실시간으로 간다
- 개인정보가 섞인 글이 게시되지 않는다 (서버 필터)
- 신고하면 즉시 격리된다
- 기간이 지난 글이 실제로 지워진다
