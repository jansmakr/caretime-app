# 1차 출시 범위

**1차는 지역 현장톡 하나다.** 2026-10-01 에 좁혔다.

보호자가 야간에 묻는 것은 "마곡동인데 애가 열이 40도예요. 어디 열었나요?" 이고
여기에는 병원 목록도, 항목별 상태도, 진료시간도 필요 없다. 그 기능은 이미 돈다 —
`hospital_id` 가 null 인 글이 올라가고 공개 목록에 보인다.

## 내린 것 (코드는 지우지 않았다)

되살리는 방법이 전부 한 파일에 있다: `src/lib/demoContent.ts`.

| 무엇 | 어떻게 내렸나 | 왜 | 되살리는 조건 |
|---|---|---|---|
| 항목별 상태 표시 | `showServiceBreakdown = false` | 3분할(봉합·화상·기타)은 "야간 소아 외상" 설계다. 1차 지역의 달빛어린이병원이 보는 것은 발열·감기·구토·설사·중이염 — 항목과 병원이 어긋나 있다 | 항목 체계를 실제 진료과목에 맞춰 다시 세운 뒤 |
| 진료시간 · 내원 마감 | `showAdmissionHours = false` | 확인된 진료시간이 한 곳도 없다. 모든 카드가 같은 "정보 없음"을 그린다 | 수동 입력 2곳의 진료시간을 확인해 넣은 뒤 |
| 좌표 · 거리 · 이동시간 | `showDemoDistance` · `showTravelEstimate = false` (이미) | 고정 데모 출발점 기준이라 '내 주변'이 아니다 | 지도 어댑터를 붙일 때 |
| 병원 로그인 · 입력 화면 | `showPartnerEntry = false` → `/partner*` not found | 참여 병원 0곳. 아무도 들어갈 수 없는 문을 보호자 화면 헤더에 붙여 두지 않는다 | 첫 참여 병원이 생길 때 |
| 공공데이터 연동 | **멈춘다.** 코드 없음 — `docs/DATA-INVENTORY.md` 의 스키마 초안과 migration 초안은 적용하지 않은 채 둔다 | 1차에 필요 없다. 지역 현장톡은 병원 목록 없이 돈다 | 2차 |
| 동시수정 409 | 코드는 그대로. 쓰는 화면이 닫혀 있어 **경로가 없다** | 병원 입력 화면이 1차에 없으므로 동시에 고칠 사람이 없다 | 병원 화면을 열 때 함께 |

판정 규칙은 아무것도 바꾸지 않았다. 접기 규칙(`mergeConservative`),
항목 판정(`deriveServiceBreakdown`), 마감 판정(`lib/hours`)은 그대로 돌고
**표시만** 닫혔다. 카드의 "전화를 앞으로 끌어올리는" 판정은 여전히 마감 상태를
읽는다 — 보여 주지 않는 것과 판정에서 빼는 것은 다른 일이다.

## 남은 것

1. 보관 기간과 삭제 로직 — **완료** (`20261004_retention_purge`, 실 DB 테스트 11개)
2. `/terms` · `/privacy` 라우트 자리 — 본문은 사용자가 준다
3. 지역 현장톡이 첫 화면에서 잘 보이는가
4. 전체 점검 + 띄워서 화면 확인

## 1차에 실제로 돌아야 하는 것

- 홈에서 현장톡으로 들어간다
- 지역을 고르지 않고도 첫 글을 쓸 수 있다
- 글이 서버에 남고 24시간 공개된다
- 다른 사람에게 실시간으로 간다
- 개인정보가 섞인 글이 게시되지 않는다 (서버 필터)
- 신고하면 즉시 격리된다
- 기간이 지난 글이 실제로 지워진다
