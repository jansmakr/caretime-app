운영 빌드(`next start`)를 띄워 실제 텍스트를 읽고 적었다. 추측한 줄은 없다.
범위와 되살리는 조건은 `docs/LAUNCH-scope.md`.

## 홈 — 결정은 하나다

```
CareTime                                      [119]

지금 문 연 곳,
먼저 물어보세요

┌──────────────────────────────────────────┐
│ 실시간 병원 상황 공유                      │
│ 지금 열었나요? 얼마나 기다리나요?           │
│ 같은 동네 보호자에게 지금 상황을 묻고,      │
│ 본 것을 알려주세요. 지역을 고르지 않아도    │
│ 글을 남길 수 있습니다.                     │
│ [ 우리 동네 현장톡 열기 → ]                │
└──────────────────────────────────────────┘
이용자 제보입니다. 방문 전 병원에 전화로 확인해 주세요.
───────────────────────────────────────────
의료기관 전화번호 · 주소
강서구 야간·휴일 진료 지정 의료기관을 등록해 두었습니다.
지금 상황은 전화로 확인하는 것이 가장 정확합니다.
[ 의료기관 목록 보기 ]
```

전에는 지역·진료 항목·방문 목적을 **먼저 묻고** 그 아래에 현장톡 배너가 있었다.
세 질문은 "야간 소아 외상 병원 찾기"의 입구이고, 답으로 나오는 것은 병원 2곳의
목록이다. 보호자가 밤에 묻는 것은 "지금 어디 열었나요?" 다.

주 버튼은 하나다. 병원 전화번호로 가는 길은 구분선 아래 보조 버튼으로 남겼다 —
전화번호는 1차에서도 가장 쓸모 있는 값이라 길을 없애지 않았다. 다만 그 칸이
약속하는 것은 **전화번호와 주소뿐**이다. 진료시간을 약속하지 않는다(없다).

## 병원 상세 — 내려간 것

| 전 | 지금 |
|---|---|
| 오늘 진료시간 / 내원 마감 카드 | 없다. 확인된 진료시간이 0곳이라 항상 "정보 없음"이었다 |
| 항목별 상태 (찢어진 상처·화상·그 밖) | 없다. 1차 지역 병원의 진료과목과 어긋난 표였다 |
| 실시간 제보 피드 + 작성 폼 (브라우저 메모리) | 이 의료기관 현장톡 (서버·현장톡과 같은 저장소) |
| 헤더 "무료 의료기관 참여" | 없다. 참여 병원 0곳 |

남은 것: 주소 · 전화 · 등록된 진료기능 · 현재 상태 · 현장톡 · 전화 버튼.

## 첫 HTML 에 글이 보인다

고쳤다. 전에는 `hydrateMessages` 가 `useEffect` 에서만 돌아서 **서버가 보낸 HTML 은
항상 0건**이었다. 느린 기기에서 첫 그림이 "아무 말도 없는 방"이고, 글이 적은 출시
직후에 그 한 순간이 제일 중요하다.

확인: 글 1건을 올린 뒤 서버 HTML 에서 `/chat` 과 `/hospital/m9282197f1e24` 둘 다
같은 글이 보인다(`1건` · 본문 · 별명). 한 저장소이므로 두 화면이 같은 글을 센다.

격리·삭제된 글이 되살아나지 않게 보관소가 지워진 id 를 기억한다
(`ChatSnapshot.removedIds`). 서버 목록에 남아 있어도 다시 올리지 않는다 —
신고로 내린 글이 되살아나는 쪽이 훨씬 나쁘다. 테스트 5개로 고정했다
(`features/chat/roomMerge.test.ts`).

## 약관 · 방침

`/terms`, `/privacy` 가 열려 있고 본문이 없는 동안은 이렇게 말한다.

```
준비 중입니다
이용약관 본문을 준비하고 있습니다. 아직 올리지 않은 문서를 방침으로
보여 드리지 않습니다.
지금 저장하는 것은 글 내용과 서버가 만든 별명뿐입니다. 글은 24시간 동안
공개되고 30일 뒤 지워집니다. 이름·연락처·위치는 저장하지 않습니다.
```

`/more` 에는 두 줄이 '준비 중'으로 있다(링크 아님). 하단 동의 문구는
문서가 준비될 때까지 **그려지지 않는다** — 빈 방침으로 가는 링크를 만들지 않는다.

없는 문이었다. 링크만 떼지 않고 라우트에서 막았다.
