# 약관 · 방침 본문을 두는 곳

`/terms`, `/privacy` 라우트가 **이 디렉터리의 파일을 그대로 읽어서** 보여준다.
본문을 코드에 넣지 않는 이유: 법무 문구는 개발자가 아닌 사람이 고치고, 고칠 때마다
배포 파일을 손대야 하면 "일단 코드에 적어 두고 나중에"가 된다.

## 넣는 방법

1. `terms.md` 와 `privacy.md` 의 `<!-- 본문대기 -->` 줄을 지운다.
2. 머리글 두 줄을 채운다.
3. 본문을 붙인다.
4. `npm run build` 로 확인하고 `/terms`, `/privacy` 를 띄워서 읽는다.

## 머리글 형식

파일 맨 위 두 줄은 고정이다. 이 두 줄을 읽어서 화면 제목과 시행일, 그리고
`guest_sessions.policy_version` 에 들어갈 값을 만든다.

```
# 이용약관
시행일: 2026-10-15
```

- `시행일` 은 `YYYY-MM-DD` 다. `미정` 이면 **아직 준비되지 않은 것으로 본다.**
- 준비되지 않은 동안: 하단 동의 문구와 링크가 **나오지 않는다.** 빈 방침으로
  연결되는 링크를 만들지 않는다. 라우트는 "준비 중"을 보여 준다.

## 내가 채워야 하는 빈칸

코드가 추측해서 넣을 수 없는 값이다. 본문에 직접 적는다.

- 운영자 표시 — 개인인지 법인인지
- 연락처 이메일
- 개인정보 보호책임자
- 시행일 (머리글 둘째 줄. 이 값이 `policy_version` 이 된다)
- Supabase 저장 지역 (처리 위탁 칸. 운영 프로젝트 설정을 보고 적는다)

## 사실 확인이 끝난 문장 (그대로 옮겨도 된다)

코드를 보고 확인한 값이다. 바꾸지 않고 쓰면 방침과 실제가 갈라지지 않는다.

> 본인이 작성한 글은 같은 브라우저에서 글 옆의 **[삭제]** 를 눌러 지울 수 있습니다.
> 누르면 즉시 모든 화면에서 사라지고, 서버에서는 보관 기간(30일) 안에 완전히
> 삭제됩니다. 처리 중인 신고가 걸린 글은 그 신고가 끝난 뒤에 삭제됩니다.

> 개인정보 처리 위탁: Supabase Inc. (데이터베이스·인증·실시간, 저장 지역
> Northeast Asia / Seoul `ap-northeast-2`)

Vercel(웹 호스팅) 리전은 **아직 정하지 않았다.** 배포 전에 정하고, 고른 값을
이 칸에 적는다. 정하지 않으면 미국 동부(`iad1`)가 된다.

백업은 **지금 없다**(복원 가능한 백업 0개, PITR 꺼짐). "백업 N일 보관"을 쓰려면
요금제를 올린 뒤 대시보드에서 실제 값을 보고 쓴다.

## 본문에 쓸 수 있는 것

줄 단위로 읽는다. 쓸 수 있는 것은 이것뿐이다.

| 쓰기 | 결과 |
|---|---|
| `## 제목` · `### 제목` | 소제목 |
| `- 항목` | 목록 |
| 빈 줄로 나눈 덩이 | 문단 |
| `**굵게**` | 굵은 글씨 |

표·이미지·링크 문법은 지금 그리지 않는다. 그런 것이 필요해지면 그때 넣는다 —
방침 본문에 꼭 필요한 것은 문단과 목록이다.

## 수정하면 무엇이 따라 바뀌는가

`시행일` 을 바꾸면 `policy_version` 값이 바뀐다. 형식은
`terms=YYYY-MM-DD;privacy=YYYY-MM-DD` 이고, 그 값을 만드는 곳은
`src/features/legal/version.ts` 한 곳이다. 왜 날짜 두 개를 함께 적는지는 그 파일에.

보관 기간을 방침에 적을 때는 **추측하지 말고** `docs/DATA-INVENTORY.md` 를 본다.
그 숫자는 DB 의 `retention_policy` 표와 테스트로 묶여 있다 — 방침에 적은 숫자와
실제로 지우는 시점이 다르면 그 자체가 위반이다.
