# 약관 · 방침 본문을 두는 곳

`/terms`, `/privacy` 라우트가 **이 디렉터리의 파일을 그대로 읽어서** 보여준다.
본문을 코드에 넣지 않는 이유: 법무 문구는 개발자가 아닌 사람이 고치고, 고칠 때마다
배포 파일을 손대야 하면 "일단 코드에 적어 두고 나중에"가 된다.

## 넣는 방법

1. `terms.md` 와 `privacy.md` 의 `<!-- 본문대기 -->` 줄을 지운다.
2. 머리글 두 줄을 채운다.
3. 본문을 붙인다.
4. `npm run build` 로 확인하고 `/terms`, `/privacy` 를 띄워서 읽는다.

## 머리글 형식

파일 맨 위 두 줄은 고정이다. 이 두 줄을 읽어서 화면 제목과 시행일, 그리고
`guest_sessions.policy_version` 에 들어갈 값을 만든다.

```
# 이용약관
시행일: 2026-10-08
```

- `시행일` 은 `YYYY-MM-DD` 다. `미정` 이면 **아직 준비되지 않은 것으로 본다.**
- 준비되지 않은 동안: 하단 링크·동의 문구가 **나오지 않고** 라우트는 "준비 중"이다.
- **시행일을 미래로 적을 수 있다**(사전 고지). 그 기간에는:
  - `/terms`·`/privacy` 가 본문을 보여 주되 "YYYY-MM-DD 부터 시행됩니다. 아직
    효력이 없습니다"를 위에 붙인다
  - 하단에는 링크만 보이고 "동의하는 것으로 봅니다"는 **적지 않는다**
  - `policy_version` 은 **null 이다.** 미래 날짜를 동의한 버전으로 적으면 없는
    동의를 있는 것처럼 기록하는 것이다
  - 시행일이 지나면 세 가지가 저절로 켜진다. 코드를 고칠 일이 없다
- 날짜는 **서울 기준**으로 견준다. UTC 로 읽으면 시행일이 하루 늦게 켜진다.

## 사업자 정보는 **본문에 적지 않는다** — 토큰을 쓴다

상호·대표자·주소·사업자등록번호·보호책임자·이메일은 `src/features/legal/company.ts`
한 곳에 있다. 푸터도 같은 값을 읽는다. 본문에 값을 직접 적으면 주소를 옮기는 날
두 곳만 고쳐지고, 어느 쪽이 맞는지 알 수 없게 된다.

본문에는 이 토큰을 쓴다. 렌더할 때 바뀐다.

| 토큰 | 지금 값 |
|---|---|
| `{{상호}}` | 주식회사 이노메딕 |
| `{{대표자}}` | 박대수 |
| `{{주소}}` | 서울특별시 금천구 디지털로10길 78, 10층 |
| `{{사업자등록번호}}` | 818-86-03381 |
| `{{보호책임자}}` | 강혁 |
| `{{이메일}}` | help@caretime.kr |

예:

```
개인정보 보호책임자: {{보호책임자}} ({{이메일}})
상호: {{상호}} / 대표자: {{대표자}} / 사업자등록번호: {{사업자등록번호}}
```

표에 없는 토큰은 **바꾸지 않고 화면에 그대로 남는다**(`{{담당자}}` 처럼). 조용히
빈칸으로 만들면 값이 빠진 문장이 공개된다. 테스트가 남은 토큰도 잡는다.

값을 바꿀 때는 `company.ts` 만 고친다. 문서는 그대로 두면 된다.

## 내가 채워야 하는 빈칸

- 시행일 (머리글 둘째 줄. 이 값이 `policy_version` 이 된다)
- Supabase·Vercel 저장 지역은 확인해서 적어 뒀다 — 둘 다 서울이다
  (`docs/DATA-INVENTORY.md` 처리 위탁)

## 사실 확인이 끝난 문장 (그대로 옮겨도 된다)

코드를 보고 확인한 값이다. 바꾸지 않고 쓰면 방침과 실제가 갈라지지 않는다.

> 본인이 작성한 글은 같은 브라우저에서 글 옆의 **[삭제]** 를 눌러 지울 수 있습니다.
> 누르면 즉시 모든 화면에서 사라지고, 서버에서는 보관 기간(30일) 안에 완전히
> 삭제됩니다. 처리 중인 신고가 걸린 글은 그 신고가 끝난 뒤에 삭제됩니다.

> 개인정보 처리 위탁: Supabase Inc. (데이터베이스·인증·실시간, 저장 지역
> Northeast Asia / Seoul `ap-northeast-2`)

Vercel(웹 호스팅) 리전은 **아직 정하지 않았다.** 배포 전에 정하고, 고른 값을
이 칸에 적는다. 정하지 않으면 미국 동부(`iad1`)가 된다.

백업은 **지금 없다**(복원 가능한 백업 0개, PITR 꺼짐). "백업 N일 보관"을 쓰려면
요금제를 올린 뒤 대시보드에서 실제 값을 보고 쓴다.

## 본문에 쓸 수 있는 것

**줄바꿈을 그대로 지킨다.** 쓴 모양이 곧 문서의 모양이다 — 조항 번호와 줄 구분은
본문의 일부다. 산문처럼 다시 흘려 쓰지 않는다.

| 쓰기 | 결과 |
|---|---|
| `## 제목` · `### 제목` | 소제목 |
| `1.` · `①` · `제3조` · `가.` 로 시작하는 줄 | **그 줄 그대로.** 번호를 다시 붙이지 않는다 |
| `- 항목` | 목록 |
| `| 머리 | 머리 |` + `|---|---|` + 행들 | 표 (아래 참고) |
| `---` | 구분선 |
| `> 문장` | 인용 블록 |
| `**굵게**` | 굵은 글씨 |

이미지·링크 문법은 그리지 않는다. 필요해지면 그때 넣는다.

### 표는 좁은 화면에서 쌓아서 그린다

**가로로 넘치지 않는 것이 표처럼 보이는 것보다 중요하다.** 360px 에서 가로
스크롤이 생기면 오른쪽 칸을 못 읽고, 방침은 끝까지 읽혀야 하는 글이다.
그래서 `<table>` 을 쓰지 않는다 — 쓰면 어느 폭에서는 반드시 넘친다.

- **두 칸 표** → 라벨/값 두 줄로 쌓는다. 좁은 화면에서도 표처럼 읽힌다
- **세 칸 이상** → 한 행을 덩이로 쌓는다. 첫 칸이 제목, 나머지는 "머리글 값"

표를 여러 개 써도 된다. 칸 수가 모자란 행은 빈 칸으로 채워 그린다 —
표가 깨지는 것보다 낫다.

구분선(`|---|---|`)이 없으면 **표로 보지 않는다.** 파이프 문자가 섞인 보통 문장일
수 있어서다.

## 수정하면 무엇이 따라 바뀌는가

`시행일` 을 바꾸면 `policy_version` 값이 바뀐다. 형식은
`terms=YYYY-MM-DD;privacy=YYYY-MM-DD` 이고, 그 값을 만드는 곳은
`src/features/legal/version.ts` 한 곳이다. 왜 날짜 두 개를 함께 적는지는 그 파일에.

보관 기간을 방침에 적을 때는 **추측하지 말고** `docs/DATA-INVENTORY.md` 를 본다.
그 숫자는 DB 의 `retention_policy` 표와 테스트로 묶여 있다 — 방침에 적은 숫자와
실제로 지우는 시점이 다르면 그 자체가 위반이다.
